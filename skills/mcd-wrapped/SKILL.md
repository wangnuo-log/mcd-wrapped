# 麦麦年报

## 这个技能解决什么

用户吃完一顿麦当劳之后，几乎没有人回头看「**我这一年到底在麦当劳吃了什么**」。
麦当劳 MCP 提供了完整的历史订单工具（`order-list`、`mall-order-list`），
但**整个榜单 100 个项目里没有一个人做复盘类内容**——大家都在做"帮你省钱"，
没人做"帮你看清自己"。

本技能把历史订单变成 **11 张竖屏叙事卡片**（Spotify Wrapped 风格），
核心是一张可以截图发给朋友的「麦麦人格」标签。

## 核心原则：取数给 MCP，算术给代码，表达给你

**不要用大模型去解析时间、分组统计、算占比。** 这些一律交给
`src/wrapped_engine/wrapped_engine.py`，因为：

- 金额用 **int 分** 运算，`0.1 + 0.2` 不会变成 `0.30000000000000004`；
- 分组、占比、极值全是查表 + 累加，**同输入必得同输出**；
- 38 项自测覆盖精度 / 边界 / 守恒 / 健壮性 / 确定性五类断言。

你的职责是：**跑脚本 → 读结果 → 用人话讲给用户听**。

## 执行流程

### 第 1 步：判断模式

- 用户首次使用 / 想看效果 / **没配 Token** → 用内置离线样本（默认行为）
- 用户要**真实年报** → 通过 MCP 拉 `order-list`，落盘后传 `--orders`

> ⚠️ **一定要先试离线样本**。没配 Token 时直接拉真实数据会失败，
> 此时用离线样本演示并告诉用户「这是脱敏示例数据，配好 Token 后能生成你自己的年报」。

### 第 2 步：跑脚本

```bash
cd src/wrapped_engine

# 离线演示（默认，无需 Token）
python wrapped_cli.py --html -o ../../docs/demo.html

# 真实订单
python wrapped_cli.py --orders my_orders.json --html -o ../../docs/report.html

# 只要 JSON 统计结果（便于你自己讲给用户听）
python wrapped_cli.py --json

# 跑自测
python -m unittest selftest -v
```

常用参数：

| 参数 | 作用 |
|---|---|
| `--html -o 路径` | 生成单文件 HTML 报告（推荐默认输出） |
| `--json` | 输出结构化 JSON 统计结果 |
| `--orders 路径` | 用真实订单 JSON（数组或含 `orders` 键的对象） |
| `--profile '{"city":"深圳"}'` | 附加用户画像，显示在报告头部 |
| `--generated-at "2026-10-12 16:00"` | 覆盖报告生成时间戳 |
| `--repo URL` | 报告尾部 Star 入口链接 |
| `--radar URL` | 姊妹项目「麦麦活动雷达」入口 |

### 第 3 步：读结果并讲给用户听

`--json` 输出的关键字段：

| 字段 | 用途 |
|---|---|
| `totals` | 总消费 / 订单数 / 件数 / 笔均 / 周期 |
| `persona.label` | **麦麦人格主标签**（报告最有传播价值的一点） |
| `persona.traits` | 全部命中标签及得分 |
| `by_slot` | 时段分布（含跨零点深夜时段） |
| `top_items` | 最爱餐品 TOP 榜 |
| `by_channel` | 麦乐送 / 堂食 / 得来速 / 自取 |
| `by_month` | 月度节奏（找高峰月份） |
| `weekday` | 工作日 vs 周末 |
| `highlights` | 最贵 / 最早 / 最多件 / 单日连击 |
| `coupon` | 用券率 / 省下金额 / 最常用的券 |
| `points` | 累计积分 |

讲法建议：先甩人格标签（最有记忆点），再讲总账，再讲高光时刻，最后给一句"下次可以试试"。

## 10 条人格规则（确定性判据，可逐条核验）

| 标签 | 条件 |
|---|---|
| 早餐信徒 | 早餐时段订单占比 ≥ 30% |
| 夜宵麦门 | 深夜时段（21:00–06:00）占比 ≥ 12% |
| 宅家麦乐送 | 麦乐送渠道占比 ≥ 35% |
| 现制派 | 到店堂食占比 ≥ 30% |
| 得来速党 | 得来速渠道占比 ≥ 12% |
| 巨无霸死忠 | 巨无霸类餐品件数 ≥ 10 |
| 甜品控 | 甜品品类件数占比 ≥ 12% |
| 薅羊毛大师 | 用券率 ≥ 30% |
| 周末战士 | 周末订单占比 ≥ 42% |
| 大额玩家 | 单笔 ≥ ¥50 订单占比 ≥ 15% |

时段划分：早餐 06–10 / 午餐 10–14 / 下午茶 14–17 / 晚餐 17–21 / 深夜 21–06（跨零点）。

## 输出规范

- 单文件 HTML，**零外部资源引用**（样式与图形全部 CSS 内联，断网可看）
- 竖屏 460px 容器，手机截图即为一张社交图
- 深色底 `#1C1C1E` + 荧光黄 `#FFC72C` + 麦当劳红 `#DA291C`，**不使用麦当劳官方 Logo**
- 报告尾部固定包含「非麦当劳官方产品」免责声明
- 支持 `prefers-reduced-motion`，动效降级

## 数据与安全

- 仓库不含任何真实 Token、密钥或真实用户订单
- 示例数据由 `src/sample_data/make_sample_data.py` **固定种子 42** 生成，可完全复现
- 用户真实订单 JSON 本地生成、本地渲染，不上传任何第三方
- MCP Token 仅通过环境变量 `MCD_MCP_TOKEN` 传入，禁止写入仓库

## 常见故障

| 症状 | 原因 | 处理 |
|---|---|---|
| `缺少 MCP Token` | 没配连接器 | 用离线样本，或配 `mcp-config.example.json` |
| 报告里时间为 1970-01-01 | 订单 JSON 缺时间字段 | 检查 `order-list` 返回，确认时间字段存在 |
| 人格显示「数据不足」 | 订单为空 | 换用真实数据，或用内置样本 |
| HTML 打开是乱码 | 编码 | 用 UTF-8 打开，脚本输出已带 `charset=utf-8` |
